## 1. What this prototype actually is

Kimi-K3 ("Kimi Workspace") is a **single-file Streamlit chat script** (`app.py`, 758 lines) that streams completions from an OpenAI-compatible endpoint at `https://api.tokenrouter.com/v1` (`app.py:229-235`), augmented by a `core/` package of ten modules providing: web search + page reading, a four-provider news pipeline, a Playwright browser agent, multi-format file ingestion, an AST-sandboxed calculator, and Markdown/JSON/DOCX export.

Three structural facts define the prototype:

- **There is no tool-calling protocol.** Tool selection is a two-branch `if`-chain of regex/substring heuristics in Python (`run_tools`, `app.py:410-438`); no `tools`/`tool_choice` is ever sent to the model (`app.py:685-692`). Tool output is prose concatenated into the **user** message (`app.py:337-341`).
- **`core/__init__.py` is not a package init — it is a monkeypatch installer.** It rebinds `web_tools.fetch_public_page`, wraps `web_tools.browse_web` twice, replaces `web_tools.search_news`, and patches `openai.OpenAI.__init__` plus the SDK's `Completions.create` **class method process-wide** (`core/__init__.py:20-22, 48`; `core/browser_direct.py:155-159`).
- **Nothing is persisted.** The only store is `st.session_state.messages` (`app.py:240`); a browser refresh or container recycle destroys the conversation. The only durable artifacts are manual download buttons (`app.py:561-576`) and the machine-global browser profile at `~/.kimi-workspace` (`core/browser_agent.py:45-48`).

## 7. Root-cause design flaws (what the git history shows was patched repeatedly)

The 33-commit history contains three re-patch cycles. Each cycle added a layer without removing the previous one.

**1. Web page reading — 6 commits, ending in a three-tier fallback plus a monkeypatch.**
`b753b20` → `58bd550` → `0b92328` ("Fix bare-domain browsing and add rendered-page fallback") → `cdaeb05` ("Add HTTP/2 support") → `3817b1b` → `cec3ca3` ("Enable local Playwright browser commands and renderer fallback"). Root cause: **the failure mode was never measured, only worked around.** Each tier (httpx → r.jina.ai → Chromium) was bolted on because the previous one returned empty text, but `_looks_blocked_or_empty` (`web_tools.py:227-232`) still treats any page under 250 chars as blocked, and the response charset is still never consulted (`:205` decodes everything as UTF-8 with `errors="replace"`). The fake `Chrome/150.0.0.0` User-Agent (`web_tools.py:55`, duplicated verbatim at `news_fallback.py:17` and `article_resolver.py:33`) is a trivially detectable bot signature — the very thing the fallbacks exist to work around.

**2. News search — 8 commits producing three complete pipelines, two now dead.**
`2049297` → `4e56a47` → `1dbf24b` (wires `search_news_robust`) → `f3ddcbd` → `bbbfa83` (replaces it with `search_news_resilient` three commits later, **without deleting the previous module**) → `b0fc279` → `b05da0d` → `18f6b4e`. Root cause: **new-module-instead-of-edit, enabled by having no tests.** Every behaviour that drove these rewrites — the `.`-splitting query destruction (`news_resilient.py:105`), the 30-hour "24-hour" window (`news_fallback.py:104`), the zero-score headline resolution (`article_resolver.py:183`), the label/content divergence (`__init__.py:41` vs `web_tools.py:712`) — is pure-function logic that a handful of unit tests would have caught. Instead each fix produced a parallel implementation, and the two date filters ended up with **opposite defaults for undated items** (`web_tools.py:374` returns `True`, `news_fallback.py:114` returns `False`).

**3. Browser-command latency — 4 commits ending in "bypass the LLM entirely."**
`154453a` ("Compact browser command context for faster responses") → `89aa656` → `773d711` ("Return explicit browser commands without an LLM call") → `aa1a0c7` ("Bypass TokenRouter for explicit browser commands"). Root cause: **the escalation ladder ran out of application-level seams, so the last step reached into a third-party library.** `browser_speed.py` compacts context and appends a model instruction; `browser_direct.py` then makes that instruction unreachable by intercepting `Completions.create` at the class level. Two live modules now solve the same problem by mutually-invalidating mechanisms, and the `/browser` grammar exists in three divergent regexes across three files.

**The unifying pattern — patch-the-symbol instead of change-the-seam.** There is no tool registry, no dependency injection, no interface, and no configuration object anywhere. `run_tools` (`app.py:410-438`) is a hard-coded two-branch chain; the third tool was therefore added by mutating module attributes from `core/__init__.py`, and the LLM bypass by mutating an SDK class. The consequences compound: correctness now depends on statement ordering enforced by a comment (`core/__init__.py:18-19`); adding one `/browser` verb requires four coordinated edits; and the same "solve prompt bloat" problem was solved twice, incompatibly. The two enabling conditions are constant across all three cycles — **no tests** (`git ls-files` shows none) and **no logging** (zero `logging`/`print` calls), so a regression is detectable only when a user notices a wrong answer, which is precisely how three news pipelines came to coexist.
